YT-SUPERTOOL - ROADMAP TICH HOP YT-DLP + FFMPEG QUA LOCAL COMPANION

MUC TIEU DU AN

Tich hop bo tai video chat luong cao vao YT-SuperTool hien tai, khong
tach thanh mot du an rieng.

Trai nghiem cai dat mong muon: 1. Cai YT-SuperTool (userscript hoac
extension) truoc. 2. Cai them goi YT-SuperTool Companion tren may tinh.
3. Companion duoc cai mot lan. Sau do YT-SuperTool tu phat hien ket noi
va xu ly tai video. 4. Nguoi dung bam nut Download ngay tren giao dien
YouTube hien co.

Uu tien: - Mien phi, khong can backend/server tra phi. - Ho tro
Userscript (Tampermonkey/Violentmonkey), Extension MV2 va MV3. - Huong
toi Windows, Linux va macOS. - Companion tu dong dong goi cac thanh phan
can thiet; nguoi dung khong phai tu cai Node.js, Python, yt-dlp hay
FFmpeg. - Giu nguyen kien truc, tinh nang va giao dien hien tai cua
YT-SuperTool toi da.

KIEN TRUC DE XUAT

YT-SuperTool UI | +– Shared Core | +– Target Adapters | +– Userscript
Adapter | +– Extension MV2 Adapter | +– Extension MV3 Adapter | +– Local
Companion API (127.0.0.1) | +– yt-dlp +– FFmpeg +– File system /

Dinh huong Companion: - Dung Node.js de phat trien Companion, phu hop

Khong xem viec dong goi la da thanh cong cho den khi co ban build va
test thuc te tren tung nen tang.

PHASE 1 - THIET KE KIEN TRUC VA API CONTRACT

Muc tieu: Thong nhat giao tiep giua YT-SuperTool va Companion truoc khi

Cong viec: 1. Chot API local va dinh dang request/response. 2. Chot quy
trinh pairing, cap token, luu token va thu hoi token. 3. Chot health
check, version check va trang thai Companion. 4. Chot mo hinh job:
queued, running, completed, failed, cancelled. 5. Chot progress, log
thong bao loi va cancel. 6. Chot settings: thu muc luu, chat luong, dinh
dang va tuy chon FFmpeg. 7. Chot quy tac validate URL va tham so. 8.
Chot chien luoc build binary theo OS/architecture. 9. Kiem tra license
va dieu kien phan phoi cua cac binary/phu thuoc.

API tham khao: - GET /api/health - GET /api/version - POST /api/pair -
POST /api/analyze - POST /api/download - GET /api/download/:id - POST
/api/download/:id/cancel - GET /api/settings - PUT /api/settings

Luu y: Day la API contract de thiet ke, khong phai yeu cau bat buoc giu
nguyen ten endpoint neu audit cho thay cach khac an toan va don gian
hon.

Dau ra: - ARCHITECTURE.md - API_SPEC.md - SECURITY.md -
BUILD_AND_DISTRIBUTION.md

Tieu chi hoan thanh: - Moi endpoint co request/response va ma loi ro

PHASE 3 - TICH HOP ADAPTER

Muc tieu: Tao mot lop giao tiep thong nhat de Shared Core khong phu

Cong viec: 1. Xac dinh interface companionClient dung chung. 2.
Userscript Adapter: - Them metadata connect can thiet cho

va error codes giua ba target. 6. Them kiem tra Companion chua cai/chua
chay/sai version/chua pairing.

Tieu chi hoan thanh: - Cung mot interface duoc dung boi ca ba target. -
Khong dua logic browser-specific vao Shared Core. - Build ca Userscript,
MV2 va MV3 thanh cong. - Khong mo rong permissions qua muc can thiet.

GOI Y MASTER PROMPT CHO OPENCODE / AI CODING AGENT

You are a senior JavaScript/TypeScript engineer working inside the
existing YT-SuperTool repository.

MISSION Integrate a local YT-SuperTool Companion powered by yt-dlp and
FFmpeg into the existing project. Do not create a separate replacement
product. Preserve the existing Download button, shared-core
architecture, adapters, build targets, settings, and unrelated features.

MANDATORY WORKFLOW 1. Audit the repository before editing. 2. Read the
existing downloader, userscript adapter, extension adapter,
background/service-worker handlers, manifests, build scripts, and
verification scripts. 3. Run the existing baseline commands: npm run
build, npm run verify, and npm run build:verify. Record actual results.
4. Create BASELINE_AUDIT.md with architecture, relevant files, current
downloader flow, permissions, risks, and baseline results. 5. Propose
the architecture, API contract, security model, packaging strategy, and
phased implementation plan. 6. Do not start large implementation until
the design and risks are documented. 7. Implement incrementally in
dependency order: Companion MVP, adapters, core/UI integration,
packaging, tests, docs. 8. After each phase, run relevant tests and
build verification. Report exact commands and results. 9. Never claim a
platform is supported unless a build artifact and real test evidence
exist.

ARCHITECTURE REQUIREMENTS - Keep the existing YT-SuperTool repository
and product. - Use a shared Companion client interface. - Keep
browser-specific APIs inside Userscript/MV2/MV3 adapters. - Build a
local Companion service using Node.js unless the audit proves a better
maintainable option. - Evaluate packaging approaches rather than
assuming a specific packager will work. - Bundle or manage yt-dlp and
FFmpeg for each supported OS/architecture. - Bind the service only to
127.0.0.1. - Provide health/version, pairing, analyze, download, job
status, cancel, and settings capabilities as documented in the API
spec. - Keep the current Download UI and integrate it with the
Companion. - Preserve a safe fallback only if it remains technically
valid and appropriate.

SECURITY REQUIREMENTS - Use one-time pairing and a cryptographically
random per-installation token. - Never embed a privileged shared secret
in public userscript/extension bundles. - Validate Origin/Host and
requests; do not rely on CORS alone. - Restrict accepted URLs to
explicitly supported YouTube URLs. - Do not expose arbitrary shell
execution, arbitrary URL fetching, or arbitrary filesystem access. -
Launch yt-dlp/FFmpeg using spawn with an argument array; never build
shell command strings from user input. - Validate output paths and
filenames. - Keep tokens out of logs and URLs. - Verify
downloaded/updated binaries and document their licenses. - Do not bypass
DRM, authentication, paywalls, access controls, or other content
protections. Only support content the user is authorized to access.

IMPLEMENTATION RULES - Follow existing project conventions and naming. -
Keep changes small and reviewable. - Do not rewrite unrelated modules. -
Do not remove the existing downloader path until the Companion path is
verified. - Add unit/integration tests for API validation, pairing, job
lifecycle, cancellation, and error handling. - Check SPA lifecycle and
prevent duplicate listeners/jobs. - Update manifests and userscript
metadata only with the minimum required permissions. - Update
documentation and third-party notices.

DELIVERABLES - BASELINE_AUDIT.md - ARCHITECTURE.md - API_SPEC.md -
SECURITY.md - BUILD_AND_DISTRIBUTION.md - Companion source code and
tests - Adapter integration - Downloader Core/UI integration -
Platform-specific build configuration and artifacts where feasible -
Updated README, installation guide, troubleshooting guide, and release
notes

FINAL REPORT FORMAT At the end, report: 1. What changed. 2. Files
added/modified. 3. Commands executed and exact results. 4. Build/test
matrix by OS and browser target. 5. Security measures implemented. 6.
Known limitations and untested platforms. 7. Remaining tasks.

IMPORTANT: Do not fabricate test results, build artifacts, platform
support, or successful downloads. If blocked by missing credentials, CI
